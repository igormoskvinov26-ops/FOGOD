# Сайт wfogod.ru — статическая сборка

Генератор на Python без зависимостей. На выходе — обычные HTML/CSS/JS
файлы, которые кладутся на любой хостинг: beget, nginx, Netlify, GitHub
Pages, папка на сервере. Ни PHP, ни базы, ни сборщика.

## Собрать

```bash
cd site
python3 build.py          # → site/public/
```

Посмотреть локально:

```bash
cd site/public && python3 -m http.server 8099
```

## Что откуда

```
site/
  data.py        единственный источник правды: контакты, семейства,
                 10 исполнений с ТТХ, применения
  build.py       генератор: собирает public/ с нуля при каждом запуске
  js/            клиентские скрипты (исходники)
    shared.js      общее: фильтрация, форматирование, пустые состояния
    katalog.js     фасеты каталога
    podbor.js      мастер подбора
    index.js       мини-подбор на главной
  public/        РЕЗУЛЬТАТ СБОРКИ. Руками не править — перезаписывается
```

`build.py` берёт разметку главной и каталога из `../design/sait.html`
и перелинковывает её под многостраничный сайт. То есть каталог
`design/` нужен для сборки, но на хостинг не заливается.

## Решение, которое стоит понимать

**Страницы исполнений и семейств генерируются статически, а не
собираются в браузере.** Для B2B это принципиально: поисковик должен
видеть расход, тонкость и давление прямо в HTML. Проверить —
отключить JS, ТТХ останутся на месте:

```bash
grep -c 'м³/ч' public/filtr/ovgd-pp.html
```

JS отвечает только за фильтрацию уже отрисованных строк. Без него
каталог показывает весь список — это рабочее состояние, а не поломка.

## Как менять содержимое

Правки в `data.py`, потом `python3 build.py`. Каталог, подбор, карточки,
семейства, счётчики и sitemap пересобираются сами.

Добавить исполнение — новая запись в `DATA`:

```python
dict(id='ovgd-pp', nm='ОВГД полнопоточный', fam='Гидродинамические',
     sub='Весь поток через фильтр…',
     princip='Гидродинамический', shema='Полнопоточная',
     regen='Самоочистка потоком', privod='Без механизма',
     sredy=['Вода','Масло','СОЖ'],
     ispoln=['Углеродистая сталь','Нержавеющая сталь'],
     q=[3, 8000], mkm=[25, None], bar=[2, 25], poteri='нет'),
```

`None` в диапазоне значит «данных нет», и это видно на сайте честно:
позиция уходит в зону «характеристики уточняются», а не исчезает из
выдачи и не получает выдуманное число.

## Что на сайте ещё не настоящее

- **Формы никуда не отправляют.** Нужен обработчик на сервере —
  см. рекомендацию 5.3 в `CLAUDE.md`: БД сайта → почта офиса и филиала →
  вебхук в CRM.
- **ТТХ уровня типоразмера нет.** В `data.py` лежат диапазоны семейств
  из презентаций. Пока инженер не даст таблицу типоразмеров, карточка
  описывает исполнение, а не конкретную позицию.
- **Блога нет.** На статике он потребует либо генерации из markdown,
  либо внешнего движка — решается вместе с развилкой §5.1.
- **Расход и давление** взяты по презентациям (см.
  `docs/kopirajt/ttx-protivorechiya.md`), расхождения не сняты.

## Дизайн

Правила, токены и запреты — `design/DESIGN.md`. Две вещи оттуда,
которые ломают вёрстку чаще всего:

- Не задавать сетку инлайновым стилем из JS — инлайн перебивает медиазапросы.
- Не писать `1fr` в грид-колонках: колонка не сжимается ниже min-content.
  Только `minmax(0, 1fr)`.

## Проверка перед заливкой

горизонтальное переполнение на 375 px, ошибки JS, 404 по ресурсам,
переходы главная → каталог → карточка → семейство → логотип. Все чисты.
При изменениях вёрстки проверку стоит повторить.
