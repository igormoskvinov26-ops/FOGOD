## 2. Ссылки на стейджинговый домен

**Проблема.** Кнопка «Перейти в каталог» в блоке «Модификации оборудования» и
логотип в футере ведут на `http://ipfed.beget.tech/`. Это остаток стейджинга:
утечка тестового домена в продакшн плюс `http://` вместо `https://`.

**Почему не чинится кликами в Elementor.** Ссылки лежат внутри JSON в
`wp_postmeta` (`_elementor_data`). Две найденные — это те, что заметны глазом;
сколько их в базе, покажет только поиск.

### Сначала посмотреть, сколько их
```bash
wp search-replace 'ipfed.beget.tech' 'wfogod.ru' --all-tables --precise --dry-run
```

### Замена, три прохода
Elementor экранирует слеши внутри JSON (`http:\/\/`), поэтому одного прохода
мало:

```bash
# 1. обычная форма
wp search-replace 'http://ipfed.beget.tech' 'https://wfogod.ru' --all-tables --precise --report-changed-only

# 2. форма с экранированными слешами — как лежит в Elementor
wp search-replace 'http:\/\/ipfed.beget.tech' 'https:\/\/wfogod.ru' --all-tables --precise --report-changed-only

# 3. остатки: голый хост без протокола
wp search-replace 'ipfed.beget.tech' 'wfogod.ru' --all-tables --precise --report-changed-only
```

`--precise` включает замену через PHP: медленнее, но корректно разбирает
сериализованные данные. Без него сериализованные массивы ломаются.

### После замены
1. Elementor → Инструменты → **Регенерировать CSS и данные**
   (или `wp elementor flush-css`).
2. Сбросить кэш плагина кэширования и CDN, если есть.
3. Проверить, что кнопка и логотип футера ведут на `https://wfogod.ru`.

### Отдельно: сам стейджинг
**Сначала проверить:** открывается ли `ipfed.beget.tech` снаружи и отдаёт ли
он копию сайта. Если да — это дубль всего контента, конкурирующий с
продакшном в выдаче. Закрыть авторизацией на уровне сервера; одного
`noindex` мало, потому что ссылки на него уже разошлись.

## 3. Год в футере

**Проблема.** `© 2025` вбит текстом и не обновится.

### Если есть Elementor Pro
Виджет с годом → динамический тег **Current Date/Time**, формат `Y`. Кода не
нужно.

### Если Pro нет
В `functions.php` дочерней темы или в плагине Code Snippets:

```php
add_shortcode( 'tekuschij_god', function () {
    return wp_date( 'Y' );
} );
```

В виджете футера: `© [tekuschij_god] ООО «ФОГОД»`

`wp_date()` берёт часовой пояс сайта, `date()` — серверный, поэтому 31 декабря
они могут разойтись. **Не править `functions.php` родительской темы** —
слетит при обновлении.

## 4. Цифра опыта

**Проблема.** На одной странице «более 25 лет» (блок 3) и «более 20 лет»
(блок 4).

**Что верно.** 25. Презентации компании дают «БОЛЕЕ 25 ЛЕТ НА РЫНКЕ», это же в
проектном контексте. Ошибочна цифра 20.

**Что сделать лучше, чем просто исправить.** Оба варианта устаревают молча и
требуют ручной правки раз в год. Заменить на год основания:

> вместо «опыт производства более 25 лет» → «на рынке промышленной
> водоочистки с 1999 года»

Год подставить фактический — мне он неизвестен. Если «на рынке» и «опыт
производства» — это правда разные даты, тогда две явные фразы, а не два числа
про одно и то же.

Проверить заодно: карточки, блог, футер — везде должна быть одна формулировка.

## 5. Слаги каталога и 301

**Проблема.** В герое главной ссылка `/fogod-nepolnopotochnye` (без слеша в
конце), в футере `/ovgd-nepolnopotochnye/`. Разные слаги для одного раздела.

### Сначала проверить
```bash
curl -sI https://wfogod.ru/shop/katalog-filtrov/ovgd-nepolnopotochnye/  | head -1
curl -sI https://wfogod.ru/fogod-nepolnopotochnye                      | head -1
```

Тот, что отдаёт `200`, — канонический. Второй превращается в 301 на первый.
Если 200 отдают оба — это дубль, и его надо схлопнуть, иначе страницы
конкурируют друг с другом в выдаче.

### Карта редиректов
Ставится плагином **Redirection** или в `.htaccess`. Слева — старое, справа —
куда:

| Откуда | Куда | Почему |
|---|---|---|
| `/fogod-nepolnopotochnye` | канонический слаг из проверки выше | опечатка в герое |
| `/shop/katalog-filtrov/gidrocziklony/` | `/shop/katalog-filtrov/gidrociklony/` | `czy` — артефакт плагина транслитерации, который передаёт «цы» как `czy` |

**Два правила, чтобы не сделать хуже:**
- никаких цепочек: A → B → C ломает передачу веса, ведите сразу на конечный;
- 301, не 302 — временный редирект вес не передаёт.

После — прогнать sitemap и проверить, что в нём только канонические адреса.

## 6. Дублированное меню

**Проблема.** Разметка меню продублирована четыре раза — десктопные и
мобильные варианты Elementor. Лишний DOM, и, что важнее, скрытые копии видны
поисковику и скринридеру, если спрятаны через `display:none`.

**Честно:** это самый трудоёмкий пункт из шести и единственный, который может
не уложиться в вечер. Если время поджимает — переносите в Этап 2, там меню
всё равно переделывается.

### Диагностика
```bash
curl -s https://wfogod.ru/ | grep -c 'menu-item'
```
Поделить на число пунктов меню — получится количество копий.

### Минимальная правка
Оставить один виджет навигации, спрятанный вариант убрать из DOM, а не
скрывать стилями. В Elementor это «Отзывчивость → скрыть на устройстве»
(удаляет из вывода), а не `display:none` в кастомном CSS.

Эти правки нашлись в презентациях; **сначала проверить**, есть ли они на

| Найдено | Правильно |
|---|---|

## Проверка после всех правок

```bash
# стейджинговый домен не должен встречаться нигде
wp search-replace 'ipfed.beget.tech' 'ipfed.beget.tech' --all-tables --dry-run
# в отчёте должно быть 0 совпадений

# смешанный контент: http:// на https-страницах
curl -s https://wfogod.ru/ | grep -oE "http://[^\"' ]*" | sort -u
```

Глазами:
- [ ] кнопка «Перейти в каталог» ведёт на `https://wfogod.ru`
- [ ] логотип в футере ведёт туда же
- [ ] год в футере — текущий
- [ ] цифра опыта одна и та же во всех блоках
- [ ] обе ссылки на неполнопоточные приводят на одну страницу
- [ ] формы отправляются (замена по базе могла задеть настройки форм)

Последний пункт не пропускать: `--all-tables` трогает и настройки плагинов,
а молча сломанная форма обратной связи — это потерянные заявки, которых никто
не заметит неделю.
